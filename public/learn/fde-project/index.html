项目背景与运行方式

模拟客户需要员工查制度、经理查预算。项目包提供 Python 标准库实现的权限检索 API、合成资料、6项自动测试与交接模板。

这是不调用大模型的可运行检索基线；请求角色为模拟，不能当作生产鉴权。先完成正确性与权限练习，再扩展模型。

下载五阶段工程任务包 ↓
python3 -m unittest -v
python3 app.py

1. 发现

访谈使用者、维护人和审批人，明确问题、基线与范围。

交付材料

需求任务书、权限矩阵。

是否明确员工不能读预算？无真实用户时是否写测量计划？

模拟客户变更

客户临时要求所有人可见预算：记录风险与待审批项。

写下取舍、待确认事项与调整后的验收范围。

2. 设计

绘制角色校验→权限过滤→检索→引用→日志，比较基线与模型方案。

交付材料

架构图、接口契约、取舍记录。

是否在检索前过滤权限？是否明确未知信息转人工？

模拟客户变更

客户扩大范围：先列依赖、成本和不做事项，再讨论优先级。

写下取舍、待确认事项与调整后的验收范围。

3. 实现

启动 API，用员工、经理和无效角色分别请求制度与预算。

交付材料

可运行代码、请求响应、失败日志。

是否运行成功？是否保留引用？无效角色是否被拒绝？

模拟客户变更

模拟接口失败：补充超时、错误提示与人工接管测试。

写下取舍、待确认事项与调整后的验收范围。

4. 验证

运行6项测试；切换 DOC_VERSION=v2 后查询，再恢复v1复查。

交付材料

评测记录、版本切换与回滚证据。

权限、未知问题、引用、无效角色、回滚是否逐项验证？

模拟客户变更

新资料覆盖不全：记录失败样例，避免只展示成功请求。

写下取舍、待确认事项与调整后的验收范围。

5. 交接

让同伴按手册启动、复测、回滚，并收集使用障碍。

交付材料

运行手册、维护人、采用计划、产品反馈。

是否能独立接手？是否区分模拟演练与真实上线？

模拟客户变更

用户不采用：先访谈阻碍，不用虚构采用率证明效果。

写下取舍、待确认事项与调整后的验收范围。
